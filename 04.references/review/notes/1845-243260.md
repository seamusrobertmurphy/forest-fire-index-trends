Subject. A national peatland carbon model that used the Drought Code of the Fire Weather Index System to predict peatland water table depth.

Establishes. Bona and others built version 2.0 of the Canadian Model for Peatlands for national greenhouse gas reporting. Its water table depth was a function of the Drought Code, chosen because the code followed a simple water balance like that of peatlands. A linear model was fitted to single water table measurements at 296 sites, each related to the Drought Code of a nearby weather station. It set water table depth at 0.045 times the Drought Code plus an intercept for each peatland class. Acrotelm thickness came from the 80th percentile of the annual maximum Drought Code, computed on a 9 km reanalysis grid for 1979 to 2015. The fitted range of the code was 78.5 to 411.8. Wildfire was the only disturbance modelled. The text named no other component of the System, rated no fire danger, tested nothing against fire activity and proposed no peatland fire danger component. Its text cited Jain and others 2018 on PDF p. 5, which its reference list did not hold.

Quotations

"The CaMP takes a simple approach to modeling hydrology for large spatial scales by using the nationally-available Canadian Fire Weather Index Drought Code to predict long-term and annual water table depth." (PDF p. 1, printed p. 1)

"Water table depth in the CaMP is calculated as a function of the Canadian Fire Weather Index Drought Code (DC), which has been shown to approximate water table decline in peatlands, as it follows a simple one-dimensional water balance approach (precipitation and evaporation) that mirrors the water balance of peatlands (Waddington et al., 2012)." (PDF p. 5, printed p. 5)

"The relationship used for the CaMP was based not on the small sample of peatland water table time series from Waddington et al. (2012) but rather on single water table measurements for many (n = 296) sites from Zoltai et al. (2000) where both records of precise peatland type and Drought Code from nearby weather stations are available." (PDF p. 5, printed p. 5)

"These single measurements of peatland water table per site were then related back to long-term DC values for the sampling date to yield a simple linear model (Eq. (1)) describing the relationship between water table (WT) depth (cm) and DC in different peatland categories" (PDF p. 5, printed p. 5)

"we calculated the annual maximum DC for every point in the forested area of Canada using a 9-km weather grid to compute DC from the NARR reanalysis (Jain et al. 2018) from 1979–2015. The 80th percentile of the maximum DC value was used to compute the water table using Eq. (1), and that distance below the surface was taken as the acrotelm thickness." (PDF p. 5, printed p. 5)

"Note that the relationship (Eq. ([1])) used to predict water table depths only predicts a range of estimated annual minimum water table depths (Table A14) that correspond to the observed range of potential Drought Codes (78.5 to 411.8) for Canada at the time of the peatland water table observation (Supplement S1)." (PDF p. 5, printed p. 5)

"The CaMP (v2.0) only includes wildfire as a potential disturbance type, and uses average depth of burn." (PDF p. 17, printed p. 17)

Bears on

- Methods, Fire Danger Systems, "The optional grassland codes that FWI2025 added [@cffdg2025fwi2025, pp. 13, 23] and the peatland components were excluded" (qmd L2467), with gap table C8. Consistent with C8. The 2025 report cited Bona among works in which peatland indicators "have been in development and testing" (GLC-X-42 PDF p. 34, printed p. 28). Bona used the existing Drought Code and defined no peatland component, so it gave no sign that one had been issued.
- Introduction, "The 2008 weather guide had warned that if the way day length entered the Duff Moisture and Drought Codes changed" (qmd L2188). Adds an instance, by inference. Bona calibrated a national carbon model on Drought Codes computed before FWI2025 existed. The text itself said nothing about versions, so whether a recomputed code would shift its water tables is untested.
